# Frozen caller qualification spectrum

| JUnit method | Finite external observation |
| --- | --- |
| `namedRecipePinsEachReceiverAndMaterializes` | Two independent receiver inputs, each from its preserved fixture; one real named SDK result each; reviewed output digest; one exact uses-line replacement; inverse replacement restores every original byte; separate materialized files from the actual SDK results. |
| `eachReceiverPostimageIsFixedPointAndManifestIsClosed` | One target path and exact preimage hash; both receiver postimages obey the same contract; named and direct owner replays emit no change. |
| `missingAndDriftedCallersRefuse` | Missing input and case drift; six source changes covering permissions, concurrency, branch filters, ignored paths, upstream reference and CRLF. |
| `duplicatesAndNoncanonicalTargetPathsRefuse` | Duplicate target, dot alias, parent-traversal alias and a literal-backslash alias on the executing POSIX host. |
| `unrelatedSourcesAndInputPermutationsArePreserved` | Another workflow and unrelated code-looking YAML remain outside the result set; forward/reverse input order has the same sole result. |
| `directNamedSerialAndTwoWorkerReplaysAgree` | Direct owner, named serial, four independent trials on two workers, then serial replay produce identical output bytes. |

The initial single-test RED uses a no-op postimage and manifest after the actual
shared-workflow commit is available. It fails because the named SDK emits zero
changes. Only the postimage and manifest postimage hash then advance for the
complete six-test run. No existing Eclipse runtime, native, ABI or SDK proof is
reexecuted by this crate. Hosted receiving gates remain separate.
